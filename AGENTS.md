# AGENTS.md — Codebase Invariants

1. **The evaluation set is never trained or tuned on.** BIRD dev questions and databases never enter training data, hyperparameter choices or checkpoint selection. Builders refuse non-`train-` ids and evaluation databases (`--forbid-dbs`); the trainer refuses records whose ids are in `--eval_tasks`; `distil/leak_audit.py` checks database names, exact and 13-gram question overlap, and re-executes every kept query.
2. **Loss only on assistant tokens.** Every training record is single-turn (system and user messages, then one response). The response and its end-of-turn token carry loss weight 1; prompt, system, chat-template and padding tokens carry weight 0, asserted for every example (`trainer/data.py`). GRPO samples (records with a reward) are never SFT data.
3. **TPU v6e dimension alignment.** Batch sizes, sequence padding lengths, length buckets and LoRA ranks are multiples of 256 (the 256x256 MXU). The trainer checks the SFT global batch and buckets, the maximum length, the loss chunk and the rank; the launcher checks the rank.
4. **Cloud resource naming.** Any cloud VM, TPU slice, bucket or GKE resource created by scripts follows `<resource>-jawadamin-<region>-MMYY` (e.g. `tpu-v6e-jawadamin-us-east5-0926`).
5. **Evergreen tracked code.** Tracked files describe what the code does, never how it was found: no investigation narrative, no run or iteration labels, no single-host measurements in code or docstrings. Working records live in the git-ignored `.agents/` directory.
6. **Every reported number is regenerated from raw logs.** Results come from graded files, trainer logs and serving benchmarks through a script (`distil/report.py`, `distil/compare.py`); no hand-set constants, and every comparison is paired and same-run.
